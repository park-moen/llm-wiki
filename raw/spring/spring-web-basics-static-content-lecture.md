네 이제 이번 시간에는 스프링 웹 개발 기초를 알아보겠습니다.

웹을 이제 개발한다는 거는 사실 여기 딱 제목 그대로 크게 세 가지 방법이 있습니다.

첫 번째는 정적 컨텐츠라는 게 있어요. 이건 뭐냐면 저 이전에 웰컴페이지 했던 것처럼 그냥 서버에서 뭐 하는 거 없이 그냥 파일을 그대로 웹브라우저에 그대로 내려 주는 거예요. 이게 이제 정적 컨텐츠라고 그러고요.

두 번째는 이제 MVC와 템플릿 엔진이라는 방식이 있는데요. 이건 뭐냐면 이제 가장 많이 하는 방식이죠. 예를 들어서 여러분 과거에 JSP, PHP 이런 거 들어보셨을 거예요. 이런 것들이 소위 말하는 템플릿 엔진이거든요. 뭔가 HTML을 그냥 주는 게 아니라 서버에서 프로그래밍해서 HTML을 동적으로 바꿔서 내리는 거죠. 이런 걸 템플릿 엔진이라고 그러고, 그걸 하기 위해서 컨트롤러, 이전에 봤던 모델, 그리고 템플릿 엔진 화면 이 세 가지를 Model, View, Controller, MVC라고 합니다. 요즘에는 이 패턴으로 개발을 많이 하죠.

그래서 정적 컨텐츠와 이제 차이는 뭐냐면 정적 컨텐츠는 그냥 파일을 그대로 고객한테, 웹 브라우저에 전달해 주는 게 정적 컨텐츠 방식의 웹 개발이고, MVC와 템플릿 엔진은 뭔가 서버에서 좀 변형을 해서 HTML을 바꿔서 내려주는 방식입니다.

그리고 마지막으로 API는 뭐냐면, 만약에 여러분이 안드로이드나 아이폰 클라이언트랑 개발을 해야 돼요. 그러면 서버 입장에서는 요즘에는 어떻게 하냐면 과거에는 XML 이런 포맷도 썼는데 요즘에는 JSON이라는 데이터 포맷으로 내려줘요. HTML 이런 걸 내리는 게 아니라 JSON이라는 데이터 구조 포맷이 있거든요. 그 데이터 구조 포맷으로 클라이언트한테 데이터를 전달하는 게 보통 요즘에 API 방식이라고 합니다.

API 방식은 또 요즘에 Vue나 React, Vue.js, React 이런 것들을 쓸 때도, API로 데이터만 내려주면 화면은 클라이언트가 알아서 그리고 정리하는 방식들을 할 때 많이 사용하고요. 그다음에 서버 간 통신할 때 서버끼리는 사실 HTML을 내릴 필요가 없잖아요. 서버끼리는 어떤 데이터가 왔다 갔다 하는지가 중요하기 때문에 이렇게 데이터가 흐를 때는 API 방식이라고 합니다. 보통은 이렇게 말하며, 깊이 있게 들어가면 정의가 달라질 수 있습니다.

이번 시간에는 이 세 가지를 하나씩 살펴볼게요. 이게 이제 제일 큰 그림이고 디테일하게는 여러분들은 이제 스프링 웹 개발 같은 것을 들어보시면 될 것 같아요.

자 먼저 정적 컨텐츠에 대해서 보겠습니다. Spring Boot는 우선 정적 컨텐츠 기능을 자동으로 제공합니다.

여기 사이트 열어볼게요. 제가 이전 시간에 이제 찾는 방법 가르쳐 드렸죠. 여기서 보면 정적 컨텐츠라고 해보시면 돼요. 영어로 되어 있는데, 스프링 기본 설정으로 Spring Boot는 정적 컨텐츠를 이 폴더에서 찾아서 제공한다고 되어 있죠.

그러면 한번 해볼게요. 여기 resources에 보면 static이라고 했죠. 이 폴더에다가 그냥 제가 아무 파일을 만들어 볼게요. `hello-static.html`이라고 만들어 보겠습니다.

`hello-static.html`이라고 만들고 여기에 그냥 HTML 코드를 작성하는 겁니다. HTML이나 resource 파일 정도는 원활하고 빠른 강의 진행을 위해서 복사 붙이기를 할게요. 이렇게 놓고 이거를 서버에서 전달해 주는 거예요.

그러면 URL을 어떻게 들어오면 되냐면 이 파일명 그대로 hello-static으로 들어오면 돼요. `localhost:8080/hello-static.html`로 들어오면 그대로 나오죠.

이 소스 보기 한번 할게요. 보면 똑같죠. 완전 100% 똑같죠. 그냥 여러분이 원하는 파일을 넣으시면 돼요. 그러면 정적 파일이 그냥 그대로 반환됩니다. 대신 여기에는 어떤 프로그래밍을 할 수는 없어요. 그냥 이거 그대로 반환됩니다. 이런 것을 정적 컨텐츠를 제공하는 기능이라고 합니다.

이거를 간단하게 원리를 설명해 드리면, 사실 이거는 제가 그냥 큰 개념으로 여러분이 이해하기 쉽게 그린 거고 Spring MVC를 본격적으로 공부하면서 깊이 있게 들어가면 또 여기 안에 여러 가지가 많이 나오거든요. 그런데 지금 이 강의의 목적 자체는 그런 디테일한 것보다 크게 어떻게 돌아가는지를 여러분 머릿속에 그려드리는 게 강의 목표예요. 너무 디테일한 것보다 상위에서 큰 그림을 보는 거라고 이해해 주시면 됩니다.

웹브라우저에서 `localhost:8080/hello-static.html`을 치니까 방금 그 결과가 나왔죠. 그럼 어떻게 되냐면 제일 처음에 여기 내장 Tomcat server가 이 요청을 받고요. `hello-static.html`이라고 왔다고 Spring한테 넘깁니다.

Spring은 먼저 Controller 쪽에서 `hello-static`이라는 게 있는지 찾아봐요. Controller가 먼저 우선순위를 가진다는 뜻이에요. 그런데 `hello-static`과 관련되어 mapping된 Controller가 없죠.

그러면 그다음에 Spring Boot가 resources 안에 있는 static의 `hello-static.html`을 찾습니다. 그렇게 해서 파일이 있으면 그냥 반환해 주는 거예요. 간단하죠? 정적 컨텐츠는 이런 식으로 됩니다.

다음 시간에는 이제 본격적으로 MVC와 템플릿 엔진은 어떤 식으로 동작하는지 한번 보겠습니다. 감사합니다.
