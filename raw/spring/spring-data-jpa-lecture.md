자 그래서 스프링 데이터 jpa는 기본적으로 인터페이스를 통한 기본적인 CRUD를
제공하고요 그리고 파인드 바이 네임, 파인드 바이 이메일처럼 메서드 이름만으로 조회하는
기능을 제공해 줍니다
그리고 페이징 기능까지 자동으로 다 제공해 줍니다
그리고 참고로 그리고 한 가지만 딱 해볼까요
여러분? 이제 뭐...
아닙니다 뭐 하여튼 기능이 있는 것들은 한번 메서드 호출해 보면서 한번 여러분 해보세요
그래서 이제 실무에서는 JPA와 스프링 데이터 JPA를 기본으로 사용을 하고 이제
실무에서는 동적 쿼리를 또 해결하기 쉽지가 않아요
그거는 또 Query DSL라는 라이브러리가 있어요
이걸 쓰면 돼요
Query DSL를 쓰면 쿼리도 자바코드로 안전하게 작성할 수 있고 동적 쿼리도 편리하게
작성할 수 있습니다
대부분 여러분 JPA를 실무에서 진짜 딥하게 하시는 분들은 이 JPA, Spring
Data JPA, Query DSL 이 기술을 다 조합을 해서 씁니다
그리고 이런 조합으로 해결하기 어려운 거는 JPA도 순수한 네이티브 SQL을 쓸 수 있게
제공을 해요 그러니까 JPA와 관련된 그 Hibernate라는 기술을 처음 만든 그 Gavin King도
100% 내가 이거를 다 이 ORM 기술을 해결하려고 만든 게 아니다 그래서
네이티브 쿼리를 쓸 수 있는 걸 열어 놨습니다
이 네이티브 쿼리는 여기 그냥 여러분이 쌩짜로 SQL을 짜는 거예요
그리고 또 필요하면 앞서 학습한 스프링, JDBC 템플릿을 같이 섞어서 쓸 수도 있습니다
그리고 JPA랑 MyBatis 같은 기술을 섞어 쓰셔도 되고요
아무튼 자세한 거는 여기 강의에서 설명드릴게요
이것만 해도 또 몇 시간 짜리 강의가 되죠
자 이렇게 해서 여러분 대단원에 막을 내렸습니다
뒤에 다음에는 AOP를 할 거고요
여기 한번 정리할게요
자 이제 Spring DB 접근 기술에 대해서 쭉 알아봤구요 저희가 먼저 H2 데이터베이스
설치해봤고 순수 JDBC 기술로 써봤구요
써봤더니 진짜 그 쿼리 하나하나가 어마어마하죠
그리고 이걸 가지고 통합 테스트 만들어 보고 그 다음에 Spring JDBC 템플릿으로
바꿔봤습니다
JDBC 템플릿은 썼더니 반복되는 코드가 굉장히 줄어들지만 SQL에 내가 직접 작성해야
됐죠. 그리고 이후에 JPA를 봤습니다.
JPA는 기본적인 CRUD 하는데 내가 그런 쿼리 같은 걸 작성할 필요가 없었어요.
물론 조금 이제 셀렉트 할 때는 JPQL이라는 걸 짰어야 됐죠.
그런데 스프링 데이터 JPA까지 오니까 아예 내가 구현 클래스를 작성할 필요가 없이
인터페이스만으로 개발이 끝나버렸어요.
그리고 마치 마법처럼 파인드 바이 네임,파인드 바이 이메일 이런 것들을 다 제공을
해줬습니다 자 그렇게 해서 이제 스프링 DB 접근 기술에 대해서 알아봤고요
자 여러분 아마 지금까지 들어보시면 아시겠지만 결국 개발이라는 게 웹 MVC도 되게
중요하고 데이터 접근 기술도 되게 중요하고 이런 ORM 기술도 되게 중요해요
그래서 실무에서는 이런 것들을 사실 두루두루 다 알고 쓰셔야 됩니다
