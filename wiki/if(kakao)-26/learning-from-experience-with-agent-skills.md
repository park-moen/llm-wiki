## Overview

Agent가 작업 중 겪은 성공과 실수를 다음 작업에 활용하려면, 경험에서 재사용 가능한 절차와 검증 방법을 추출해 보관해야 한다. Anthropic은 스킬의 작성·평가 원칙을, Letta는 실행 기록에서 스킬을 만드는 과정을, ACE는 실행·회고·지식 정리를 분리하는 구조를 설명한다. 이 문서는 사용자가 제공한 if(kakao) 발표 이미지의 레슨 축적 흐름을 이해하기 위한 보충 자료이며, 외부 글이 해당 발표 자체를 설명하거나 그 효과를 검증했다는 뜻은 아니다.

## Anthropic: 실제 작업에서 드러난 부족한 점을 스킬로 보완한다

Agent Skills는 지침·script·참고 자료를 묶어 필요한 작업에서 불러오는 구조다. 전문 지식을 매번 대화에 설명하는 대신 재사용할 수 있는 자원으로 보관한다.

Anthropic의 Developing and evaluating skills 절은 다음과 같은 운영 방법을 제안한다.

1. 대표 작업을 실행하고 agent가 어려워하거나 추가 설명을 필요로 하는 부분을 찾는다.
2. 발견한 부족한 점을 해결하도록 스킬을 점진적으로 만든다.
3. 실제 사용에서 스킬 선택과 실행 흐름을 관찰하며 개선한다.
4. 성공한 접근과 흔한 실수를 재사용 가능한 지침·코드로 기록하고, 잘못된 실행은 회고한다.

따라서 스킬은 처음부터 완성된 지침을 예상해 작성하는 방식뿐 아니라 실제 경험을 통해 개선하는 방식으로도 만들 수 있다. 스킬 선택에는 이름과 설명이 중요하며, 관련 본문과 참고 자료는 필요할 때 읽는 progressive disclosure 방식을 따른다.

이 글은 Agent Skills를 만든 조직의 공식 기술 설명이다. 스킬 구조와 작성 원칙을 확인하는 일차 자료로 적합하지만, 사람이 모든 레슨 후보를 승인해야 한다거나 기획·구현·검증 역할별로 반드시 나눠야 한다는 절차를 정하지는 않는다.

## Letta: 실행 기록을 회고한 뒤 스킬을 생성한다

Letta의 Skill Learning은 실행 기록인 trajectory에서 재사용할 스킬을 만드는 과정을 설명한다.

| 단계 | 원문에서 수행하는 일 |
|---|---|
| Reflection | 과제 해결 여부, 추론의 타당성, 단계의 정당성, 경계 사례와 추상화할 반복 패턴을 평가 |
| Creation | 회고를 바탕으로 가능한 접근법·흔한 함정·검증 전략을 담은 스킬 생성 |
| 후속 활용 | 유사한 작업에서 저장한 스킬을 agent가 다시 참고 |

단순히 이전 대화를 통째로 붙이는 것과, 실패 원인과 대응 절차를 추출해 스킬로 만드는 것은 구분한다. 원문은 과거 오류를 그대로 context에 포함하는 것이 성능에 해로울 수 있다는 문제에서 출발한다.

실험은 스킬을 쓰지 않는 경우, 실행 기록만으로 만든 스킬을 쓰는 경우, 실행 기록과 verifier의 테스트 피드백으로 만든 스킬을 쓰는 경우를 비교한다. 저자들은 검증 피드백을 함께 사용한 스킬이 실패 방식과 효과 없는 접근을 더 잘 담는다고 보고한다. 이 결과는 해당 benchmark와 설정에서 얻은 것이며, 새로운 화면이나 실무 프로젝트에서도 같은 개선이 보장된다는 뜻은 아니다.

Letta는 이 방식을 model의 가중치를 바꾸지 않고 경험을 활용하는 방법으로 설명한다. 스킬을 Markdown 파일로 관리하므로 Git으로 이력을 남기고 다른 agent와 공유할 수 있다. 다만 회고 후 스킬 생성에 반드시 사람의 승인을 거치도록 설계된 절차는 아니다.

## ACE: 실행·회고·지식 정리를 분리한다

Agentic Context Engineering은 context를 계속 개선되는 playbook으로 다룬다. 논문에서 역할은 다음과 같이 나뉜다.

| 역할 | 책임 |
|---|---|
| Generator | 현재 지침을 사용해 작업하고 실행 기록 생성 |
| Reflector | 성공·실패에서 구체적인 교훈을 추출 |
| Curator | 교훈을 기존 context에 통합할 항목별 변경으로 정리 |

Curator가 만든 변경은 가벼운 비LLM 코드로 기존 context에 병합한다. 매번 전체 문서를 다시 요약하기보다 관련 항목을 추가·수정하고 중복을 정리하는 방식이다. 항목에는 재사용 가능한 전략, 도메인 개념, 흔한 실패 방식 등을 담을 수 있다.

이 설계는 반복적인 전체 재작성으로 중요한 세부 지식이 사라지는 context collapse를 피하려는 것이다. 교훈을 축적하더라도 적용 조건과 구체적인 실패 대응을 잃으면 다음 작업에서 유용하지 않을 수 있다는 점을 설명한다.

다만 **ACE의 Curator는 사람의 승인 담당자가 아니다.** 논문은 회고의 품질에도 의존한다. Reflector가 유용한 교훈을 추출하지 못하면 context가 잡음이 되거나 해로울 수 있으며, 단순한 작업에서는 자세한 지침을 계속 늘릴 필요가 없다고 밝힌다. 논문의 실험을 실무에서 사람의 개입이 계속 줄어든다는 직접 근거로 쓰지 않는다.

## 발표 이미지의 흐름과 연결해서 읽기

다음 표는 세 원문의 설명을 발표 이미지의 흐름에 대응시킨 해석이다. 발표 구현을 확인한 결과나 세 자료가 동일한 시스템을 설명한다는 주장이 아니다.

| 이해할 단계 | 연결되는 근거 | 구분할 점 |
|---|---|---|
| 실행 | Anthropic의 대표 작업 평가, Letta의 trajectory, ACE의 Generator | 재사용할 교훈을 판단할 실행 기록이 필요 |
| 회고 | Anthropic의 실패 회고, Letta의 Reflection, ACE의 Reflector | 기록 보관과 원인·대응 방법 추출은 다른 작업 |
| 레슨 후보 | Letta의 접근법·함정·검증 전략, ACE의 항목별 교훈 | 후보가 생겼다는 사실만으로 정확성이 보장되지 않음 |
| 사람의 검토·승격 | 세 자료를 참고해 추가할 수 있는 운영 절차 | 모든 원문에 공통으로 정의된 필수 단계는 아님 |
| 역할별 스킬로 재사용 | Anthropic의 작업별 스킬, Letta의 스킬 공유, ACE의 다음 실행에서 지식 재사용 | 기획·구현·검증 역할별 분리는 적용 조직이 선택할 설계 |

### 적용 예시: 누락을 검증 가능한 행동으로 바꾸기

아래는 원문의 실험 사례가 아니라, 이 문서에서 구성한 운영 예시다.

화면 작업에서 상태 복원 요구가 누락되었다면, 주의하라는 문장만 추가하기보다 다음처럼 레슨 후보를 작성할 수 있다.

- 적용 조건: 화면을 벗어났다가 돌아오는 사용자 흐름이 있을 때.
- 기획: 무엇을 복원할지와 복원하지 않을 예외를 요구사항에 명시한다.
- 구현: 상태의 보관 위치와 복원 시점을 결정한다.
- 검증: 이동 전 상태, 복귀 동작, 복귀 후 기대 상태를 확인한다.
- 검토: 특정 화면에서만 유효한 규칙인지, 비슷한 작업에 재사용할 수 있는지 사람이 판단한다.

이런 사람의 검토는 잘못된 회고를 일반 규칙으로 굳히지 않기 위한 운영 제안이다. 세 자료는 경험의 축적과 재사용을 뒷받침하지만, 그 결과로 사람의 개입이 항상 줄거나 새로운 작업의 성공이 보장된다고 입증하지는 않는다.

## 자료별 활용 범위

- **Anthropic 공식 기술 글:** 스킬 구조, 경험 기반 개선, 평가 방법의 일차 자료다. 사람의 레슨 승격 체계 자체를 검증한 연구는 아니다.
- **Letta 기술 보고:** 구현 주체가 학습 과정과 benchmark 비교 방법을 공개한 자료다. 보고된 개선을 다른 프로젝트에 그대로 적용하지 않는다.
- **ACE 논문:** 실행·회고·지식 정리의 분리와 점진적 지침 갱신을 설명하는 연구 자료다. 이 문서는 명시한 arXiv 원문 버전을 사용하며, 회고 품질에 따른 한계도 함께 반영한다.
