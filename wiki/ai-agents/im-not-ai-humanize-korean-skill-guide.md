## Overview

`im-not-ai`의 `humanize-korean` Skill은 한국어 초안에서 번역투, 기계적인 구조, 상투적인 결론, 접속사·수식·완곡 표현의 반복처럼 AI 글에서 자주 나타나는 문체 패턴을 찾아 국소적으로 윤문한다. 목표는 사실이나 주장을 새로 쓰는 것이 아니라 원문의 의미·장르·격식을 유지하면서 표현과 리듬을 자연스럽게 만드는 것이다. Codex에서는 단일 호출 Fast Path를 제공하고, Claude Code에서는 글의 상태에 따라 light·standard·heavy 경로를 선택한다.

## 이 Skill이 하는 일과 하지 않는 일

적합한 작업은 다음과 같다.

- ChatGPT·Claude·Gemini 등으로 만든 한국어 초안의 AI 문체 완화
- 영어 번역투와 피동 표현 정리
- 반복되는 접속사, 결론 관용구와 형식명사 축소
- 과도한 불릿·헤딩·볼드·이모지 정리
- 원래 주장과 정보를 보존하는 문체 중심 윤문

다음 작업은 별도로 처리해야 한다.

- 단순 맞춤법·오탈자 교정
- 번역
- 새로운 사실이나 논거 추가
- 사실 확인과 출처 검증
- 학술 제출이나 저널리즘 진실성 보증

저장소도 이 도구의 목적을 AI 탐지기 우회가 아니라 한국어 글쓰기 품질 개선으로 규정한다.

## Codex에서 가장 빠르게 사용하기

Codex용 Skill은 Fast Path만 제공한다. 설치는 저장소를 clone한 뒤 다음 명령으로 연결한다.

```bash
git clone https://github.com/epoko77-ai/im-not-ai.git
cd im-not-ai
./install.sh --codex-only
```

설치 후에는 `$humanize-korean`으로 호출하거나 `/skills` 메뉴에서 선택한다.

```text
$humanize-korean

아래 글의 의미, 수치, 고유명사는 그대로 보존하고
AI 번역투와 기계적인 문장 구조만 자연스럽게 윤문해줘.
장르: 기술 블로그
강도: 보수

[원문]
```

파일을 입력할 수도 있다.

```text
$humanize-korean draft.md
장르: 리포트
강도: 기본
최소심각도: S1
```

Codex용 공식 옵션은 다음 세 가지다.

| 옵션 | 선택지 | 의미 |
|---|---|---|
| `장르` | `칼럼`, `리포트`, `블로그`, `공적` | 허용할 문체와 구조를 결정 |
| `강도` | `보수`, `기본`, `적극` | 원문 유지와 수정 폭의 균형 조정 |
| `최소심각도` | `S1`, `S2`, `S3` | 어느 정도의 패턴부터 고칠지 지정 |

원문을 최대한 살리고 싶으면 `강도: 보수`, 뚜렷한 AI 패턴만 제거하고 싶으면 `최소심각도: S1`부터 시작하는 편이 안전하다.

## Codex와 Claude Code의 차이

| 실행 환경 | 처리 방식 | 적합한 상황 |
|---|---|---|
| Codex | 한 번에 탐지·윤문·자체검증하는 Fast Path | 비교적 짧은 글을 빠르게 윤문 |
| Claude Code light | 진단을 생략한 보수적 단일 윤문 | 이미 잘 쓴 글 |
| Claude Code standard | 진단 후 겨냥 윤문 | 일반적인 AI 초안 |
| Claude Code heavy | 진단·윤문·finalize | 중증 패턴, 장문, 검증 증적이 필요한 작업 |

Codex Skill 문서는 `5,000자 이하` 한국어 텍스트를 Fast Path 대상으로 설명한다. 정밀한 다중 호출 검증이 필요하면 Claude Code의 `--strict` 경로를 권장한다.

## 윤문의 네 가지 최상위 원칙

1. **의미 불변**: 사실, 주장, 인과관계를 바꾸지 않는다.
2. **톤 유지**: 격식체를 구어체로 바꾸거나 칼럼을 문학적 에세이로 바꾸지 않는다.
3. **국소 수정**: 문제가 발견된 구간만 고친다.
4. **빼기 중심**: 원문에 없던 비유, 수사, 상투구를 새로 넣지 않는다.

변경률이 `30%`를 넘으면 과윤문 가능성을 경고하고, `50%`를 넘으면 중단·롤백 대상으로 본다.

## 무엇을 AI 문체로 판단하는가

| 분류 | 대표 패턴 | 수정 방향 |
|---|---|---|
| A. 번역투 | `~에 대해`, `~를 통해`, `~에 있어서`, 이중 피동 | 목적격·능동형과 자연스러운 조사로 단순화 |
| B. 영어 과다 | 영어 병기 반복, 광고성 buzzword | 첫 등장만 병기하거나 자연스러운 한국어로 풀이 |
| C. 구조 | 기계적인 불릿·헤딩·대구·이모지 | 의미 있는 구조만 남기고 산문에 통합 |
| D. 관용구 | `결론적으로`, `시사하는 바가 크다` | 삭제하거나 구체적인 결론으로 교체 |
| E. 리듬 | 같은 길이와 종결어미의 반복 | 문장 길이와 종결 방식을 자연스럽게 변주 |
| F. 수식 | `매우`, 중복 수식, `~적/~성/~화` 누적 | 불필요한 수식 삭제, 구체 동사 사용 |
| G. Hedging | `~할 수 있을 것으로 보인다` | 필요한 완곡만 남기고 단계를 줄임 |
| H. 접속사 | `또한`, `따라서`, `즉`의 문두 반복 | 흐름이 유지되면 삭제 |
| I. 형식명사 | `것이다`, `점`, `바`, `필요가 있다` 반복 | 직접적인 주어·동사 문장으로 변경 |
| J. 시각 장식 | 볼드·따옴표·대시 남용 | 실제 강조와 인용만 보존 |

## 자주 쓰는 치환 감각

다음은 기계적으로 전부 치환하는 사전이 아니라, 문맥을 보고 적용하는 방향이다.

| 딱딱하거나 번역투인 표현 | 자연스러운 방향 |
|---|---|
| `X에 대해 논의한다` | `X를 논의한다` |
| `X를 통해 Y한다` | `X로 Y한다`, `X해서 Y한다` |
| `AI에 의해 생성된` | `AI가 만든` |
| `경쟁력을 가지고 있다` | `경쟁력이 있다`, `경쟁력이 강하다` |
| `변화가 크다는 것이다` | `변화가 크다` |
| `결론적으로` | 결론 문단에서는 삭제를 우선 검토 |
| `시사하는 바가 크다` | 삭제하거나 실제 의미를 직접 서술 |

핵심은 표현을 무조건 짧게 만드는 것이 아니다. 원문의 확실성, 장르와 말투를 보존하면서 불필요한 중간 표현을 걷어내는 것이다.

## 절대로 자동 수정하면 안 되는 항목

다음은 AI 문체처럼 보여도 의미가 바뀔 위험이 있어 탐지와 윤문에서 제외한다.

- 고유명사, 인명, 기관명, 제품명과 모델명
- 수치, 날짜와 단위
- 큰따옴표 안의 직접 인용
- 법률과 규정 조문
- 수학·화학·통계 표기
- `LLM`, `GPU`, `MCP`, `API` 같은 업계 표준 영어 약어
- 문맥상 필요한 학술 개념어

## 결과를 확인하는 방법

Codex Fast Path는 cwd 아래 `_workspace/{run_id}/final.md`에 윤문본을 저장한다. 결과 끝의 `HUMANIZE-SUMMARY`에는 원문·윤문본 글자수, 변경률, 패턴별 탐지 수, 자체검증 결과, 등급과 주요 변경 내역이 기록된다.

확인 순서는 다음이 실용적이다.

1. 수치·날짜·고유명사·직접 인용이 그대로인지 본다.
2. 원문의 주장과 인과관계가 유지됐는지 비교한다.
3. 격식과 장르가 바뀌지 않았는지 확인한다.
4. `결론적으로`, `또한`, `것이다`를 다른 상투어로 단순 교체하지 않았는지 본다.
5. 변경률이 높다면 전체 결과를 바로 채택하지 말고 변경 구간을 검토한다.

## 결과가 마음에 들지 않을 때의 요청법

전체를 다시 돌리기보다 문제가 있는 범위를 좁힌다.

```text
이 문단만 다시 윤문해줘. 수치와 technical term은 그대로 둬.
```

```text
번역투만 더 손봐줘. 원문 톤은 유지하고 구조는 바꾸지 마.
```

```text
윤문 강도를 보수로 낮춰줘. 이전 결과에서 의미가 달라진 부분은 원문으로 롤백해줘.
```

```text
접속사와 결론 관용구만 정리해줘. 새로운 비유나 설명은 추가하지 마.
```

이 방식은 재윤문할 때 또 다른 AI 문체를 새로 집어넣는 위험을 줄인다.
