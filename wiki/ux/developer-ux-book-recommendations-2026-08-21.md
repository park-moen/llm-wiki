# 개발자를 위한 한국어 UX 도서 추천

> Sources: [개발자를 위한 한국어 UX 도서 근거 가이드](developer-ux-book-evidence-guide.md)
> Archived: 2026-08-21

## Overview

개발자가 UX를 처음 체계적으로 공부한다면 『UX/UI의 10가지 심리학 법칙』과 『사용자를 생각하게 하지 마!』를 먼저 읽는 편이 좋다. 국내 UX 프로젝트 과정이 궁금하면 『찐 UXer가 알려주는 UX/UI 실무 가이드』를, 기획자·디자이너와의 협업 맥락이 필요하면 『오늘도 개발자가 안 된다고 말했다』를 이어서 선택한다. 이 순서는 2026-08-21에 확인한 출판 정보와 실제 독자 후기를 바탕으로 한 시점 고정 판단이다.

## 추천 순서

### 1. UX/UI의 10가지 심리학 법칙 개정증보판

프론트엔드 개발자가 가장 먼저 읽기 좋은 책이다. 다른 서비스의 화면을 그대로 모방하는 데서 벗어나 버튼 위치, 선택지와 화면 구성을 UX 원칙으로 설명하는 출발점을 제공한다. 얇고 사례 중심이라 입문 장벽이 낮지만 UX 전체를 다루는 책은 아니므로, 작업 중 다시 찾아보는 참고서로 사용한다.

### 2. 사용자를 생각하게 하지 마!

명료한 화면, 내비게이션과 사용성의 기본 질문을 익히는 책이다. 사례의 외형은 오래됐지만 사용자가 화면을 이해하고 탐색하는 원칙은 여전히 활용할 수 있다. 한국어판은 대체로 학습에 사용할 수 있으나 영어 말장난이나 애매한 표현은 원문을 함께 확인한다.

### 3. 찐 UXer가 알려주는 UX/UI 실무 가이드

한국 조직에서 UX 프로젝트와 UI 문서가 어떻게 진행되는지 간접 경험하는 용도로 적합하다. 특히 프로젝트 경험이 적어 기획자·UX 담당자의 산출물과 대화 맥락이 낯선 개발자에게 유용하다. 이론의 깊이보다 현장 과정에 초점을 맞추며, 도서 제공 리뷰가 포함되었다는 점을 감안한다.

### 4. 오늘도 개발자가 안 된다고 말했다

UX 설계 원칙보다는 기획자·디자이너·개발자가 서로 다른 사고방식과 언어를 사용한다는 사실을 이해하는 책이다. 협업에서 요구사항의 배경을 놓치거나 “안 된다”는 답변 뒤의 제약을 충분히 설명하지 못하는 경우에 읽는다. 비개발 직군이 주 독자이므로 기술 설명보다 상대 직군의 관점을 파악하는 데 초점을 둔다.

## 최소 구매안

한 권만 고르면 『UX/UI의 10가지 심리학 법칙』, 두 권을 고르면 여기에 『사용자를 생각하게 하지 마!』를 더한다. 이후 현재의 문제가 프로젝트 흐름인지 협업인지에 따라 나머지 두 책 가운데 하나를 선택한다.

## 읽은 뒤 적용하기

현재 개발 중인 화면 하나를 골라 다음을 기록한다.

- 사용자가 별도 설명 없이 목적과 다음 행동을 알 수 있는가?
- 선택지와 정보의 양에는 설명 가능한 이유가 있는가?
- 버튼 위치와 명칭은 익숙한 사용 패턴에 맞는가?
- 오류가 발생했을 때 원인과 회복 방법을 알 수 있는가?
- 기획자와 디자이너의 요청에서 목적과 기술적 제약을 분리해 대화했는가?

책의 개념을 실제 화면과 협업 대화에 적용한 뒤 결과를 확인해야 독서가 실무 지식으로 전환된다.
