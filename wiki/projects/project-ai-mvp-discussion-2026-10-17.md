# 프로젝트의 AI 챗봇 MVP 출시 검토

> Sources: 사용자와 AI agent의 현재 대화 — 사용자의 KPI 설명·정정과 AI agent의 구현·비용 제안
> Archived: 2026-10-17
> Type: 대화 기반 archive

## 기록의 성격과 익명화

이 문서는 기존 Wiki 지식을 종합한 글이 아니라, 프로젝트의 AI 기능 출시를 논의한 대화의 보관본이다. 사용자에게 확인한 사실과 AI agent의 제안을 구분한다. 서비스 실명은 제목·본문·파일명 모두에서 `프로젝트`로 치환했다. 원본 대화 전문과 raw 파일은 저장하지 않는다.

이 기록은 대화 당시의 판단을 보관하며, 구현 완료나 비용 확정을 뜻하지 않는다. 외부 자료를 새로 수집하지 않았고, 기존 Wiki에는 프로젝트 관련 자료가 없었다.

## 사용자에게 확인한 배경과 KPI

- 이미 사주 풀이를 제공하는 MVP 프로젝트를 보유하고 있다.
- KPI 중 하나는 AI를 도입한 MVP 서비스 하나를 출시하는 것이다.
- 사용자는 기존 프로젝트에 AI 기능을 추가해 출시하는 것이 KPI라고 명확히 확인했다.
- 자체 AI 모델 구축은 KPI가 아니다.
- 사용자가 검토하는 기능은 RAG를 통한 사주 풀이 챗봇이며, RAG 설정·모델 준비·API 연동 비용을 궁금해했다.

따라서 기존 프로젝트에 AI 챗봇을 추가하고 실제 사용자가 이용할 수 있게 공개하는 방향이 논의의 목표다. 기존 서비스의 기능 출시도 KPI로 인정되는지 다시 확인해야 한다는 초기 답변의 유보는 사용자의 정정으로 해소되었다.

## AI agent가 제안한 구현 방향

### 자체 모델 구축과 API 연동의 구분

기존 AI 모델의 API를 연동해 챗봇을 구현할 수 있으며, 자체 모델 학습이나 GPU 서버 운영은 이 접근의 필수 조건이 아니다.

RAG는 질문에 관련된 자료를 검색해 AI가 답변할 때 참고하도록 전달하는 방식으로 설명했다. 검색용 embedding(문장을 검색용 숫자로 바꾸는 처리)도 기존 모델을 활용할 수 있다는 제안이다. 프로젝트의 자료 규모와 현재 시스템을 확인하지 않았으므로, 구체적인 검색 방식이나 저장소는 정하지 않았다.

### 자체 모델 없이 기존 모델 API로 구현할 수 있는 이유

프로젝트에서 필요한 것은 사용자 질문과 사주 자료를 바탕으로 설명을 생성하는 기능이다. 기존 언어 모델이 가진 문장 이해·생성 능력을 API로 이용하고, 프로젝트에 필요한 사주 결과와 해석 자료를 요청에 함께 전달하는 방식으로 구현을 시작할 수 있다. 프로젝트의 모든 지식을 모델에 미리 학습시켜야만 답변을 만들 수 있는 것은 아니다.

여기서 말하는 API는 기존 AI 모델에 답변 생성을 요청하는 API다. 도구를 선택하고 여러 작업을 수행하는 AI agent 전용 API나 별도의 agent 시스템이 필수라는 뜻은 아니다.

| 역할 | API를 활용한 구현에서 담당하는 곳 |
|---|---|
| 문장 이해·답변 생성 | 외부 제공자의 기존 AI 모델 |
| 모델 학습·추론 서버 운영 | 외부 모델 제공자 |
| 사용자 사주 결과 제공 | 프로젝트의 기존 계산·조회 로직을 재사용할 수 있는지 확인 |
| 관련 사주 자료 선택 | 프로젝트가 구성하는 RAG 검색 처리 |
| 응답 범위·말투·자료 활용 지시 | 프로젝트 서버에서 API에 전달하는 지침 |
| 사주 외 질문 제한·품질 검증·사용량 관리 | 프로젝트에서 별도로 구현하고 검증할 처리 |

이 구조에서는 프로젝트가 모델의 학습 데이터·학습 코드·GPU 서버를 직접 준비하는 대신, 모델 사용량에 따른 API 요금을 지불한다. RAG도 질문마다 참고할 자료를 제공하는 역할이므로, 자체 모델 학습 없이 연결할 수 있다. 다만 API가 대체하는 것은 모델의 학습·추론 운영이며, 자료 정리·검색·채팅 화면·서버 연동까지 대신 완성해 주는 것은 아니다.

자체 모델 구축은 처음부터 모델을 학습하는 방식, 기존 모델을 추가 학습하는 방식, 기존 모델을 직접 서버에서 운영하는 방식을 구분해서 판단해야 한다. API 방식으로 요구하는 품질을 달성하기 어렵거나 외부 전송 제한·직접 운영 요구·실제 사용량에 따른 비용 문제가 확인된다면, 추가 학습이나 직접 운영을 비교할 이유가 생긴다. 현재 프로젝트에서 이런 필요성이 확인된 것은 아니므로, 우선 기존 모델 API와 RAG로 목표 품질과 비용을 달성할 수 있는지 검증하자는 제안이다.

따라서 자체 모델 구축이 불필요하다는 설명은 API 방식의 품질과 비용이 이미 검증됐다는 결론이 아니다. KPI가 모델 소유가 아닌 AI 기능 출시이고, 필요한 기능을 기존 모델과 프로젝트의 자료·로직을 조합해 구현하는 경로가 있으므로 자체 모델 구축을 선행 조건으로 두지 않아도 된다는 뜻이다.

### 제안한 MVP 범위

기존 사주 결과를 설명하고 사용자의 후속 질문에 답하는 챗봇부터 시작하는 방안을 제안했다. 기존 시스템이 만세력·오행 등을 계산하고 있다면 계산 결과를 AI에 전달하고, AI가 설명과 대화를 맡도록 역할을 나누는 구상이다. 실제 계산 로직의 존재나 재사용 가능 여부는 확인되지 않았다.

검토한 RAG 흐름은 다음과 같다.

1. 사용자의 질문을 받는다.
2. 기존 시스템에서 사용자 사주 결과를 조회한다.
3. 보유한 해석 자료에서 질문에 관련된 내용을 검색한다.
4. 사주 결과·검색 자료·질문을 AI API에 전달한다.
5. 생성된 설명을 사용자에게 제공한다.

### 사용자가 RAG 도입을 검토하는 목적

사용자는 사주 분야에 집중한 챗봇을 저렴한 API 사용료로 운영하기 위해 RAG 도입을 검토하고 있다. 목적은 다음과 같다.

- 사주 관련 자료를 근거로 풀이의 정확도와 일관성을 높인다.
- 사주 분야에 맞춰 응답을 최적화하고, 사주와 무관한 질문에는 답변하지 않는다.
- 필요한 자료만 전달하고 저가 모델을 활용하는 방안 등을 통해 API 사용료를 줄인다.

사용자가 표현한 사주 관련 학습의 최적화는 위 목적을 뜻한다. RAG는 모델 자체를 재학습하는 방식과 구분하며, 검색한 사주 자료를 답변 시 참고하도록 전달하는 방식으로 검토한다.

사주 외 질문을 제한하는 처리와 비용 절감 효과는 RAG 도입만으로 보장되지 않는다. 질문 범위 판단·응답 지침과 함께, 실제 답변 품질·입출력량·검색 비용을 검증해야 한다. 저가 모델로 필요한 품질을 달성할 수 있는지도 아직 확인하지 않았다.

RAG 자체는 KPI의 필수 조건이 아니지만, 사용자는 답변 품질·응답 범위·운영 비용이라는 목적을 가지고 도입을 검토하고 있다. 자료가 적으면 직접 전달하는 방식부터 시작하자는 AI agent의 초기 제안은 사용자가 확정한 구현 순서가 아니다.

## 비용에 관해 논의한 내용

비용은 모델 사용료뿐 아니라 자료 준비와 서비스 개발을 함께 봐야 한다.

| 구분 | 검토할 내용 |
|---|---|
| 자료 준비 | 사주 해석 자료 정리, 사용 권한 확인 |
| 검색 구축 | 자료 분할, embedding 생성, 저장, 관련 자료 검색 |
| AI API 사용료 | 질문·참고 자료·대화 기록의 입력과 답변 출력에 따른 과금 |
| 서비스 개발·운영 | 채팅 화면, 서버 연동, 사용량 제한, 서버·저장소 운영 |
| 품질 검증 | 사주 결과와 답변의 일관성, 한국어 답변 품질 확인 |

AI agent는 소규모 MVP에서는 API 사용료보다 자료 정리와 답변 품질 검증의 개발 공수가 더 클 가능성이 있다고 설명했다. 이는 프로젝트를 조사해 산출한 견적이 아니라 당시의 잠정 판단이다.

대화에는 저가 모델을 가정한 API 사용료 계산 예시가 있었으나, 프로젝트의 예상 사용량·모델·답변 길이가 미정이므로 이 archive에는 예시 금액을 예산이나 최신 요금으로 옮기지 않는다. 당시 계산은 검색·embedding·서버·세금 등을 제외한 답변 생성 비용이었고, 모델 선택·대화 기록 길이·추가 추론·재시도에 따라 달라질 수 있다는 설명이었다. 실제 예산을 잡을 때는 선택한 모델의 공식 최신 요금으로 다시 계산해야 한다.

## 아직 확인하거나 결정하지 않은 사항

- 기존 사주 계산·풀이 시스템의 구조와 결과 데이터 재사용 가능 여부
- 보유한 사주 해석 자료의 양·품질·사용 권한
- 예상 월 사용자 수와 사용자당 질문 횟수
- 사용할 AI 모델과 요구하는 한국어 답변 품질, 저가 모델의 적합성
- 사주 외 질문을 판별하고 답변을 제한하는 방식
- RAG의 구체적인 검색·저장 방식과 답변 품질·총운영비 개선 효과
- MVP의 상세 출시 범위와 답변 품질 검증 기준

기존 프로젝트의 AI 기능 출시가 KPI라는 점과, 답변 품질 향상·사주 분야로 응답 제한·API 사용료 절감이 RAG 도입 검토의 목적이라는 점을 확인했다. 구체적인 구현 방식, 모델, 일정과 예산은 검토 단계다.
